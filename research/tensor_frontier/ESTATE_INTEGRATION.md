# Tensor frontier: estate integration

## Purpose

The tensor frontier track is not a new source of theorem authority.  It is a
cross-cutting research method for turning literature formulations into
algebraic, accelerator-friendly experiments and then routing surviving
observations back into the repositories that own the mathematics.

The integration spine is:

```text
domain question
    |
    v
algebraic contract + representation variants
    |                         owned here
    v
MAX/Mojo empirical search
    |
    +----> engineering profile / negative result
    |
    v
candidate witness or anomaly
    |
    +----> Julia independent replication
    |
    +----> semantic representation-equivalence check
    |
    v
exact finite reconstruction
    |
    +----> reusable exact kernel extraction when generic
    |
    v
domain-owned checker / Lean proof
    |
    v
domain repository claim ledger
```

No arrow transfers authority upward merely because the implementation is fast,
independent, or machine-produced.

## Repository roles

### llm-kernel-lab — discovery and representation laboratory

Owns:

- T/A/C representation experiments;
- the transcendental firewall;
- MAX/Mojo empirical kernels that are not yet reusable exact infrastructure;
- benchmark corpora and performance measurements;
- anomaly/witness generation;
- experiment manifests and reproducibility envelopes.

May emit E0-E3 artifacts under the local evidence ladder.

Does **not** own domain theorem status.

### finite-math-kernels — reusable exact implementation layer

Receives a kernel only after its mathematical contract is stable and useful in
more than one domain.

Candidate extractions from this program include:

- exact Gram construction and Gram determinants;
- rational/projective rotor operations;
- exact rank and minor predicates;
- algebraic tensor contraction over supported exact scalar types;
- canonical witness encodings;
- deterministic parallel reductions whose semantics are already fixed.

The extraction rule is: first prove usefulness and semantics in the lab, then
promote the generic exact mechanism.  Experimental frontier-specific policy
stays here.

### julia-oracle-lab — independent evidence

Owns independent implementations used to return only:

```text
agrees
disagrees
inconclusive
oracle_error
```

Initial tensor uses:

- replay candidate Gram/rank witnesses;
- reproduce candidate facet residuals;
- cross-check tensor contractions on bounded corpora;
- independently recompute selected phase-transition statistics;
- replay exact reconstructed anomalies before claim promotion.

Julia agreement is evidence, never certificate acceptance.

### semantic-categorical-oracle — representation semantics

Best use: register narrowly scoped normative contracts for questions such as:

- do T-form and A-form encode the same proposition?
- does an algebraic rotor presentation preserve the intended composition law?
- does a projective ratio presentation preserve the defined/undefined cases of
  the source formulation?
- does a tensor-index normal form preserve the declared contraction semantics?

This repository may be normative only for an explicitly registered semantic
question.  It does not prove the mathematical theorem expressed by either
representation.

### domain repositories — claim ownership

The domain repository always owns:

- hypotheses;
- theorem/conjecture status;
- interpretation of exact witnesses;
- promotion from evidence to accepted domain claim;
- publication language.

The tensor lab should import a *question contract* from a domain repository and
return artifacts, not copy its theorem ledger.

## First adoption pilots

### Pilot A — closure-fiber-of-multiplication-research

This is the cleanest immediate mathematical adoption because it already treats
Gram data, quadratic étale algebras, norm-one tori, and identity fibers as
first-class objects.

Use the lab for:

1. batched trace-Gram invariant computation for Nielsen tuples;
2. structured contraction/rank experiments for representation-derived closure
   data;
3. paired LLM prompts comparing classical angle/phase language with the
   repository's algebraic torus/Gram formulation;
4. exact anomaly export back to the domain repo.

Do not move its novelty or theorem claims into this lab.

### Pilot B — height-pairings-bsd-interfaces

The incidence layer contains matrix/tensor workloads that can benefit from the
same empirical machinery without making finite fields a prerequisite.

Use the lab for:

1. family-scale construction of restriction/incidence matrices;
2. batched evaluation of local correction forms;
3. rank/nondegeneracy reconnaissance over parameterized examples;
4. comparison of determinant-heavy formulations with Gram/incidence
   factorizations;
5. exact witness reconstruction for exceptional degeneracy.

The domain repository remains responsible for height-theoretic interpretation
and BSD/Tate interfaces.

### Pilot C — finite-math-kernels extraction

After Pilots A/B expose common primitives, extract only the pieces with a
domain-independent exact contract.  The first likely promotion candidates are
`gram_determinant`, projective rotor composition, exact mode-Gram formation,
and exact rank/minor witnesses.

This is a promotion of reusable computation, not of empirical conclusions.

### Pilot D — Julia replication lane

For every E2+ tensor experiment, define a Julia replay record containing:

```text
experiment_id
problem_contract_hash
input_corpus_hash
candidate_witness
expected predicate
Mojo revision
oracle revision
```

The Julia lane must be implemented independently enough to catch shared
assumptions, not as a mechanical translation of Mojo.

### Pilot E — LLM algebraization study

Use existing theorem/certificate problems from multiple domain repositories to
construct representation pairs:

- **T-form:** conventional trig/angle/phase exposition when it exists;
- **A-form:** Gram, quadratic, rotor, projective, or polynomial exposition;
- **C-form:** explicit contraction/index form where appropriate.

Only include a pair after semantic equivalence is reviewed.  Hold the Lean
statement/verifier fixed and compare verified pass@k, leakage, proof size, and
verification cost.

This creates a research result about model representation bias independent of
whether the underlying mathematical theorem is new.

## Candidate use in established research programs

### Closure / multiplication fibers

High fit.  The program's existing avoidance of analytic primitives makes it a
direct test bed for the algebraic representation thesis.

### Height pairings

High fit for empirical family sweeps, incidence-factorization experiments, and
rank/nondegeneracy reconnaissance.  Keep the geometric height layer
field-independent.

### PSC and tiling programs

Use the tensor lab selectively for methodology, not to retensorize the whole
problem.  Good transfers are:

- corpus/benchmark discipline;
- evidence grading;
- exact replay records;
- representation-bias experiments on proof obligations;
- Mojo optimization for genuinely contraction/rank-heavy subproblems.

Existing finite automata and substitution combinatorics remain in their native
form when tensorization adds no mathematical value.

### Finite Mandelbrot / Julia-set programs

Likewise, use the lab only where multilinear/rank structure naturally appears
or for LLM representation experiments.  Exact orbit/certificate machinery
should not be rewritten merely to fit the tensor program.

### Cryptographic / RFFT work

Potentially strong future fit for algebraic rotors, structured contractions,
mode-Gram kernels, and tensorized batched experiments.  Security claims remain
in their cryptographic claim system and require cryptographic reductions or
accepted certificates, never performance evidence.

## Research workflow

Every cross-estate experiment should follow these gates.

### Gate X0 — question ownership

Name the domain repository and exact question.  If no domain owner exists, the
work remains an exploratory lab question.

### Gate X1 — algebraization

Produce the A/S/D transcendental audit.  If a source analytic quantity is
replaced only by a surrogate, rename the research question accordingly.

### Gate X2 — semantic equivalence

For paired representations, record why the propositions are equivalent.  When
the equivalence is nontrivial, register or prove it before using the pair in an
LLM comparison.

### Gate X3 — empirical kernel

Implement/benchmark the MAX/Mojo search kernel.  Output remains E0-E2 unless an
exact witness is reconstructed.

### Gate X4 — independent replay

Replay selected candidates through Julia or another independent implementation.

### Gate X5 — exact reconstruction

Convert the observation into a finite exact object: rational/algebraic
coefficients, minors, facet normals, decomposition records, or another
domain-defined witness.

### Gate X6 — domain acceptance

Send the reconstructed artifact to the domain-owned checker or proof layer.
Only this gate can change theorem/certificate status.

### Gate X7 — reusable extraction

If a mechanism is now stable and cross-domain, migrate it to
`finite-math-kernels` with its own exact boundary and provenance.

## Anti-patterns

Do not:

- centralize all research claims in `llm-kernel-lab`;
- treat a faster kernel as stronger mathematical evidence;
- convert every matrix problem into a tensor problem;
- call a surrogate an algebraization;
- use Julia agreement as proof;
- let a semantic-normalization oracle authorize a theorem;
- extract frontier-specific heuristics into `finite-math-kernels`;
- make a domain repo depend on MAX/Mojo merely to verify an already finite
  certificate.

## Immediate implementation order

1. Closure-fiber trace-Gram pilot.
2. Shared exact Gram/rank corpus.
3. Julia replay contract for that corpus.
4. T/A/C paired theorem corpus with semantic equivalence records.
5. First Mojo `mode_gram` and `batched_rank` kernels.
6. Height-pairing incidence pilot.
7. Review common primitives for extraction into `finite-math-kernels`.
8. Only then scale to moment-polytopes, tensor PCA, PEPS, and tensor dynamics.

This order gives the lab an internal dogfood loop on research we already
understand before using it to make claims about unfamiliar tensor frontiers.
